## Phase 0：基础搭建（第 1-2 周）

**目标**：项目能跑起来，素材能看到，框架能用。

| 任务 | 预计耗时 | 说明 |
|------|---------|------|
| 清理现有 Off Trail 代码 | 3h | 保留框架层（JulyArch/Core/Luban/YooAsset），移除 Off Trail 特有的 Store/System/View |
| 购买并导入素材 | 2h | Niao_K 药铺 Tileset、Herbal Icons、Chinese Fantasy Music、方舟像素字体 |
| 搭建主场景 | 4h | 用 Tileset 搭建药庐内景 + 灵田的基础场景，确认素材风格统一 |
| 定义命名空间和模块目录 | 2h | `SpiritHealer.*` 命名空间，按 GDD 模块建好文件夹结构 |
| 创建空 Store/System 骨架 | 3h | 8 个模块的 Store + System 空壳注册到 GameContext |
| Luban 表骨架 | 4h | 创建所有配置表的 Excel/JSON 定义，先填 3-5 条测试数据 |

**Phase 0 交付物**：
- 游戏能启动，看到药庐场景
- 所有 Store/System 已注册，Luban 表能读取
- 素材风格确认，截图发朋友圈的程度

## Phase 1：核心循环（第 3-8 周）

**目标**：实现最小核心 loop——**来客上门 → 望闻问切 → 开方 → 看到结果**。

### 第 3-4 周：望闻问切 + 药材基础

| 任务 | 预计耗时 | 依赖 |
|------|---------|------|
| `DiagnosisStore` + `DiagnosisSystem` 实现 | 8h | Luban `tbdiagnosis` |
| 四诊交互 UI（选择诊法 → 显示结果文本） | 6h | DiagnosisSystem |
| `InventoryStore` + `InventorySystem` 实现 | 4h | 复用 Off Trail 代码 |
| 药柜 UI（查看/选择药材） | 4h | InventoryStore |
| Luban `tbherb` 填入 15-20 种基础药材数据 | 3h | - |

### 第 5-6 周：处方 + 来客

| 任务 | 预计耗时 | 依赖 |
|------|---------|------|
| `PrescriptionSystem` 实现（君臣佐使组方 + 疗效计算） | 10h | tbherb, tbprescription |
| 开方 UI（选四味药 → 确认 → 结果反馈） | 6h | PrescriptionSystem |
| `VisitorSystem` 实现（来客生成 + 病症分配） | 6h | tbvisitor, tbcause, tbsymptom |
| 来客 UI（来客面板 + 对话） | 5h | VisitorSystem |
| Luban 填入 10 个基础病症 + 对应方剂规则 | 3h | - |

### 第 7-8 周：成长 + 时间 + 串联

| 任务 | 预计耗时 | 依赖 |
|------|---------|------|
| `ProgressionStore` + `ProgressionSystem`（声望 + 四诊经验） | 5h | - |
| `TimeSystem` 行为驱动时间（ConsumeTime 推进游戏内分钟） | 3h | 已有 TimeStore/TimeSystem 骨架 |
| 日循环串联：行为消耗时间，过营业时间自动打烊，玩家选择结束当天 | 4h | TimeSystem |
| 药理笔记 UI（记录诊断结果和方剂） | 6h | DiagnosisStore, PrescriptionStore |
| 整体流程测试 + Bug 修复 | 6h | 全部 |

**Phase 1 交付物**：
- 完整的一天循环可玩：来客上门→望闻问切（消耗时间）→开方→结果→声望变化→打烊/结束当天
- 15-20 种药材，10 个病症
- 药理笔记可查阅
- **这是你的第一个"能看到效果"的里程碑——写完代码立刻能玩**

## 关键风险与对策

| 风险 | 对策 |
|------|------|
| Phase 1 结束后觉得"不好玩" | Phase 1 就是验证核心 loop 的。如果来客→诊断→开方本身不有趣，在 Phase 1 就调整，不要带着问题往下走 |
| 数值设计（药效/声望/成长曲线）不平衡 | 所有数值在 Luban 表中，不动代码就能调。EA 期间根据反馈持续调整 |
| 美术风格不统一 | Phase 0 就确认风格。所有素材先过一遍统一色板处理再导入 |
| 系统过于复杂上手难 | 新手引导分层教学：第一天只教望诊+开方，后续逐步开放其他诊法和种植 |
| 做到一半又想加新系统 | 严格遵守 GDD 边界。新想法记到 `docs/design/ideas-backlog.md`，EA 后再评估 |
